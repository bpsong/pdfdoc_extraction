# Process your first document

Ask your administrator for the app address, your password, the pipeline name
and version for your document type, and the files/results you should expect.
A **pipeline** is the chosen sequence of processing steps. Its **version** is a
saved set of settings. A **batch** is work submitted together; it may contain
several PDFs. A split can create **child documents** from one original PDF.

## Sign in and find your way

1. Open the supplied address, select the **operator** account, enter its
   password and select **Sign In**.
2. Use the left navigation menu. When it is collapsed, point to an icon to
   display its name. If you cannot sign in, check the account and any cooldown
   message, then contact your administrator if needed.

| Work area | Everyday purpose |
| --- | --- |
| **Upload & Process** | Submit PDFs and reach the processing dashboard. |
| **Review Queue** | Check/correct extracted information or choose manual split boundaries. Completed decisions are in History. |
| **Failures** | Read a failed step's explanation and examine the source PDF. |
| **Reports** | See activity summaries and find recent batches. |

**Processing Overview**, **Extraction** and **Split Results** are reached from
the relevant batch/document; they are not all separate left-menu entries.
The Admin configuration areas are unavailable to operators. Ask your
administrator about a missing pipeline or unsuitable form rather than looking
for settings in these pages.

## Follow one document through processing

1. Open **Upload & Process**. Under **1. Select a pipeline**, choose the approved
   name and published version. Open **Pipeline details** to read its instructions;
   opening the details alone does not select it.
2. Select or drag your PDFs into **2. Upload PDFs**. Check the filenames and
   displayed limits. Submit separate batches for different document processes.
3. Select **Start processing** once and keep the page open during transfer.
   A successful upload means the files were accepted; it is not the final result.
4. On the processing dashboard, confirm the assigned pipeline/version and each
   document's **Status**, **Current step** and **Last completed** step.
5. If review is required, open **Review Queue**. Claim the item, compare values
   against the PDF, correct permitted fields and select **Complete Review**.
   For **Manual split**, decide page boundaries instead using its own guide.
6. Return to the batch dashboard. Review completion allows processing to
   continue; later output steps can still be running or fail.
7. Open **Extraction** to compare **Extracted Value** and **Final Value**.
   Check all child documents when splitting occurred, then confirm the required
   output files using the location agreed with your administrator.

To return later, open **Reports**, find **Recent Batches**, select your batch
and choose **Open processing dashboard**. Record the batch identifier shown
on screen if you need to hand work over or request help.

For an approved incoming folder, copy complete PDFs there and find their batch
in Reports. A file leaving the folder only means it has been taken in; check
the app for the outcome.

## A worked everyday example

An invoice is accepted and later appears in Review Queue because its total
needs checking. You claim it, compare the total with the PDF, correct it and
use **Preview Diff** to inspect the change. **Save Draft** keeps unfinished
work; **Complete Review** submits the checked values. After returning to the
queue, check the batch again and confirm its remaining steps finish. On
Extraction, the original and final totals can differ and the field can show
**Corrected**. Its original confidence can remain low; that does not reopen a
completed review.

If a result is uncertain, check existing work before submitting the PDF again.
